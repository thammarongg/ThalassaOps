# v0.1 — definition

**Status:** Proposed. Supersedes nothing; narrows `sprint-plan.md` for one release.
**Updated:** 2026-09-15 — aligned with the AIOps Command Center design
**Milestone:** Sprint 19, "Read-only AI Beta"
**Companion:** [`2026-09-10-direction-review.md`](./2026-09-10-direction-review.md)

## What v0.1 is

> A local-first desktop console that investigates a Kubernetes incident, explains it with
> citations to live evidence, and never sends a secret to a hosted model.

One operator, one machine, one cluster. Read-only throughout. No mutation of any connected
system, no team features, no server component.

That sentence is the release. Anything that does not serve it is out, however finished it
already is.

## The claim v0.1 makes

Two claims, both testable, and nothing beyond them:

1. **Findings cite their evidence.** Every statement the assistant makes points at the
   signal it came from, and where evidence is missing the finding says so rather than
   filling the gap.
2. **Operational data does not leave the machine unredacted.** Secrets, credentials,
   tokens, private keys and regulated data are blocked before any hosted provider request
   is made, and a policy validation failure stops the request rather than degrading it.

Claim 2 is the differentiator. Every AI SRE product in the review is a CLI, an agent or a
SaaS backend; none of them can make it. It is also the claim that cannot be wrong once,
so it carries the heaviest test burden in the release.

## Who it is for

A platform or DevOps engineer who already runs Kubernetes with Prometheus and Loki, who
cannot or will not send cluster data to a vendor, and who wants a second opinion on a
failing workload without granting anything write access.

Not for: teams needing shared state, anyone wanting automated remediation, anyone without
an existing telemetry stack.

## What ships

### Already built (Sprints 1–17, carried into v0.1 as-is)

- Tauri 2 desktop shell, local workspace, OS-keychain credentials, capability-scoped IPC
- Connector registry and health
- Kubernetes read-only foundation and resource workspace
- Prometheus, Alertmanager, Grafana, Loki and OpenTelemetry retrieval
- AWS, Azure and GCP inventory
- Operations Console, resource and service topology
- Signal normalization, security findings, correlation, change intelligence
- Incident domain, lifecycle and Incident Workspace
- AI provider gateway: hosted and local providers, fallback order, per-request budgets, audit store (no window budget is configurable until Sprint 20)

### New in v0.1

**Redaction and context control (Sprint 18)**

- Public / Internal / Confidential / Restricted classification
- Immutable secret detection and blocking
- Drop, mask, hash, truncate and aggregate actions
- Policy-runtime-backed send / store / display / export / audit separation
- Context selection, deduplication and summarization
- Redaction preview, and defined policy-failure behaviour

**Read-only AI investigation (Sprint 19)**

- Tool registry with capability scopes
- Five Kubernetes analyzers: CrashLoopBackOff, OOMKilled, Pending, probe failure, image
  pull failure
- Evidence retrieval from Prometheus, Loki and OpenTelemetry
- Structured findings, hypotheses and confidence
- Evidence citations and missing-context warnings
- AI Assistant Log

**Pulled forward from later sprints, in thin slices only**

- Secret-leak tests (from Sprint 25) — the whole of what is taken from that sprint
- Unsigned DMG on GitHub Releases (from Sprint 27) — no notarization
- Launch (from Sprint 28) — without the release-candidate process

**Visual system** — the [AIOps Command Center spec](../design/aiops-command-center.md)

- Shell, token layer and Incident Workspace restyle — built and merged
- Topology — required to match the spec's node-edge graph; the current rendering does
  not show dependency, so it cannot be screenshotted
- Investigation view for Sprint 19 findings — designed in Claude Design first, then built
  under the [UX/UI change playbook](../design/ux-ui-change-playbook.md)
- Evidence Tide Line — the incident timeline rail, built with Sprint 19's narrative
  rewrite (governance reconciliation design, Section 5)

## What is explicitly excluded

Each of these is deferred with a reason, not forgotten.

| Excluded | Reason |
| --- | --- |
| Any mutating action | v0.1 is read-only by definition. Nothing to approve, so no approval framework. |
| Policy Center (Sprint 20) | A single operator needs a policy file, not an administration surface. |
| Approval and action framework (Sprint 21) | Follows the first mutating action, which is not in v0.1. |
| Terminal and runbook workflows (Sprint 22) | Large surface; does not affect whether the investigation is any good. |
| Jira, Slack, Discord, PagerDuty (Sprint 23) | Four integrations, weeks of work, and they show nothing the evidence graph does not. |
| Multi-organization team access (Sprint 24) | Contradicts the local-first single-operator position that makes v0.1 distinctive. |
| Windows and Linux builds | macOS-first is already the plan's assumption. Cross-platform validation follows adoption. |
| Notarization and code signing | Requires a paid Apple Developer account. Right-click-open is acceptable for early users, and the README will say so. |
| Performance and scale work (Sprint 26) | Optimising for load that does not exist. |
| Restyling correlation, environments, observability, changes and AI providers beyond the shared tokens | Secondary screens; none appear in the demo. Immediately after launch. |

## What the demo shows

Ninety seconds, no narration required, recorded against the local k3s cluster with one
deliberately broken workload.

1. The Operations Console opens: the KPI strip and active incidents, every connector
   healthy.
2. A workload enters CrashLoopBackOff. The signal arrives; the console surfaces impact
   before detail.
3. The operator opens the incident. The investigation view assembles: finding, hypothesis,
   confidence — each statement citing the log line, metric or event behind it — and the
   Evidence Tide Line shows the investigation moving through the incident.
4. One source is stale. The affected finding carries a missing-context warning rather
   than a confident answer, and its "Show evidence" disclosure names the source that
   could not be read.
5. The redaction preview shows what was sent to the model and what was withheld. A secret
   in the log output appears masked.
6. Nothing was mutated. The AI Assistant Log records the whole run.

Step 4 is the one that distinguishes this from every demo in the category. It should not
be cut for time.

## Definition of done

v0.1 ships when all of the following hold.

**Functional**

- [ ] The five analyzers produce findings against fixture incidents, replayably
- [ ] At least one investigation runs end to end against a real failure on the local k3s
      cluster, not a fixture
- [ ] Every finding in that run cites retrievable evidence, or states what is missing
- [ ] The redaction preview shows sent and withheld content for that run

**Safety — the claim that cannot be wrong**

- [ ] A test corpus containing secrets and noisy telemetry is redacted correctly
- [ ] A policy validation failure blocks the request; nothing leaves the application
- [ ] Secret-leak tests cover every path that can reach a hosted provider
- [ ] Under induced failure — pod evicted mid-investigation, network partition to the tool
      endpoint, credential expired mid-run — the assistant reports an indeterminate result
      rather than asserting a cause. This is the hardest criterion here and the one worth
      writing up publicly.

**Presentable**

- [ ] Operations Console, Topology and Incident Workspace all match the AIOps Command
      Center spec
- [ ] Topology renders dependency; the direction and depth filters visibly change it
- [ ] Screenshots of all three, in the default dark theme
- [ ] Ninety-second recording of the sequence above
- [ ] README opens with what it does and a screenshot, not with npm install
- [ ] DMG attached to a tagged GitHub release, with a plain note about the unsigned build

**Gates**

- [ ] Four frontend gates green; Rust suite green; CI green on the release commit
- [ ] Contrast verified by computation, not by jsdom — `vitest-axe` skips the
      colour-contrast rule entirely

## What v0.1 does not claim

Stated plainly here so it is stated plainly everywhere else.

- It is not production-ready, and the README should not imply that it is.
- It has no users yet, so nothing about reliability at scale is known.
- The analyzers cover five failure modes. Anything else gets no useful answer.
- The local-first position is a design choice, not a proven market gap. No competitor
  found in review occupies it; that is not proof none exists.
- Model quality is not evaluated. v0.1 proves the evidence and safety plumbing, not that
  any given model reasons well about Kubernetes.

## What decides v0.2

The week after launch, not this document. Whoever files an issue, asks for a connector or
tries to use it on something unexpected reorders sprints 20 through 28. Until then those
sprints stay as written and unstarted.
